## 2. 核心使用流程与交付目标

| 流程 | 用户应能完成的动作 | 成功条件 |
| --- | --- | --- |
| 第一次打开 | 看到完整默认舞台，找到播放、示例和玩法 | 无需先缩放页面或猜测图标 |

## 3. UX-01：移动端手势重新分工

### 3.1 当前代码与排查假设

涉及 `src/main.ts` 的 `touchPoints`、`pinchFromTouches`、pointer 事件；`src/scene.ts` 的 `orbit`、`pan`、`zoom`。

已确认：双指中心位移调用 `studio.orbit(...)`，没有调用已有的 `studio.pan(...)`。因此“双指不能平移，只能旋转”有直接代码原因。

缩放有实现，但存在需要验证的两个问题：

1. 每次事件只有距离差大于 2px 才执行缩放，却无条件更新上一次距离。缓慢捏合时连续的小位移可能一直被吞掉。
2. 距离差先乘 0.16，再在 `zoom` 中乘 0.012，最终是每 CSS px 约 0.00192 世界距离；相机距离较大时变化可能难以感知。

另检查 pointercancel、指针捕获、双指跨越 UI 边界及自由相机旋转后的状态。以上是根因线索，不能在真机验证前宣布缩放问题已经解决。

### 3.2 推荐手势契约

| 输入与区域 | 行为 | 是否改曲谱 |
| --- | --- | --- |
| 单指点空网格 | 放置一个音符 | 是，一次撤销 |
| 单指在空网格拖动 | 连续绘制 | 是，一笔一次撤销 |
| 单指点已有音符 | 选中并显示编辑条 | 否 |
| 单指在音符上超过拖动阈值 | 移动音符 | 是，落定后一次撤销 |
| 单指在舞台背景拖动 | 旋转相机 | 否 |
| 双指同向拖动 | 平移相机 | 否 |
| 双指张合 | 缩放相机，可同时平移 | 否 |
| 双指扭转 | 首版不映射旋转，避免与缩放混杂 | 否 |
| 点击“适配舞台” | 恢复当前可见窗口的可用构图 | 否 |
| 在面板或按钮上操作 | 交给 UI，不穿透到舞台 | 取决于控件 |

保留桌面背景拖动旋转、中键平移、空白处滚轮缩放、音符滚轮调音。双指平移是相机移动，不等同于改变曲谱时间窗口；长曲跳转继续使用进度条，不在本轮把二者混成一个手势。

### 3.3 状态机与多指接管

建议把输入协调提取为 `src/gestures.ts`，由 main 注入“绘制、拖动、相机”的操作，不让该模块直接读写 localStorage 或构造音频节点。

状态：`idle → pending-note / paint / orbit → two-finger → wait-release → idle`。

- 音符按下先进入 pending-note；初始建议阈值：鼠标 4px、触屏 8px，以 CSS px 计算，真机测试后再调整。
- 小于阈值松手仅选择，不产生历史、移动音效和落点计算；超过阈值才开始拖动，按下坐标作为起点，避免首次移动跳跃。
- 第二根手指进入舞台时，多指导航优先。撤回本次尚未结束的绘制/拖动，恢复手势前快照，不保留第一根手指造成的误放音符，不产生新的撤销条目。
- 只回滚当前活动事务，不能撤销之前已经完成的笔触。若现有绘制已经触发保存调度，取消或覆盖该调度，确保回滚后的状态才被保存。
- 两指变一指后进入 wait-release；剩余手指移动不能立刻变成绘制或旋转。所有手指离开才重新允许单指动作。
- pointercancel、lostpointercapture、切后台、打开抽屉、旋转屏幕均显式结束或取消当前事务，清理指针集合和预览。
- 三指及以上：维持最初两根有效手指或进入 wait-release；首版推荐 wait-release，避免换指时基准跳动。
- 多指只从舞台指针建立，不把点击面板的手指加入舞台手势。

### 3.4 缩放与平移算法

用两指中心和距离的起始基准计算，不再使用“每次事件 >2px 才缩放”的方式。

- 记录起始距离 `d0`、起始相机距离 `z0`；建议 `targetDistance = clamp(z0 × d0 / d, min, max)`，手指张开时拉近。
- 极小距离做保护，例如 `d0` 与 `d` 取至少 8 CSS px。缩放上下限根据当前可见窗口和有效视口计算，不能只针对默认 16 列写死。
- 如需消抖，使用相对于手势起点的累计阈值；一旦越过阈值，保持连续跟手，不能每帧重新吞掉小变化。
- 平移以中心点位移映射到当前相机方向和舞台平面；优先复用现有 `pan`，验证俯视、正视、竖屏旋转 90° 后的方向。
- 缩放尽量以双指中心对应的舞台点为锚，缩放前后求该点投影并补偿平移，避免舞台向屏幕中心突然滑走。
- 锚点射线无法与舞台平面稳定相交时，退回相机目标点缩放，不产生 NaN、突然翻转或大幅跳动。
- 每帧合并指针更新，使用固定起始基准计算目标变换，避免两个 pointermove 事件先后到达造成累积漂移。
- 拖动期间相机快速跟手；松手首版不加惯性平移或旋转，优先保证定位可控。

### 3.5 验收

- 慢速与快速捏合都能连续缩放，不要求“大动作”才生效。
- 双指同向移动只改变平移，方位角/俯仰角在数值容差内不变；音符集合与历史深度不变。
- 距离由 100px 到 150px，目标相机距离约为原来的 2/3，受合法边界限制；阈值和缓动不应改变最终结果。
- 第一指先落在空格或已有音符，再加入第二指，结束后曲谱与手势开始前一致。
- 依次抬起手指、切后台或旋转设备后，不出现粘住的拖动或额外音符。
- 真机 Android Chromium 系浏览器和 iOS Safari 都完成验证；自动化模拟只能补充，不能替代真机。

## 4. UX-02 / UX-07：横竖屏布局与舞台有效视口

### 4.1 布局原则

响应式同时考虑宽度、高度、输入能力和浏览器可视区域。仅使用 `max-width:900px` 不足以覆盖“手机横屏宽但很矮”的场景。

建立一个共享的舞台可用矩形 `StageViewport { left, top, width, height }`，由布局层测量并传给场景。相机适配、网格拾取、屏幕投影和浮动读数必须使用同一套坐标基准。

建议 canvas 容器本身占据有效矩形，控制栏位于独立布局区域；如保留全屏 canvas，则必须在相机偏移、投影和拾取中统一应用矩形，不能只缩小相机 aspect 而仍按整屏拾取。

### 4.2 三种布局

| 模式 | 初始判定建议 | 顶部 | 舞台 | 底部/侧边 |
| --- | --- | --- | --- | --- |
| 桌面 | 宽度 ≥1024 且高度 ≥600 CSS px | 完整品牌、视图、工具 | 主视觉，避开固定控制区 | 完整播放栏、材料列表 |
| 竖屏/窄屏 | 宽度 <600，且不属于低高度横屏 | 紧凑品牌、视角入口、设置、更多 | 独立伸缩区域 | 材料入口、编辑条、播放栏 |
| 低高度横屏 | 宽>高且高度<500；优先于桌面宽度判断 | 紧凑顶栏 | 使用剩余区域，不被材料覆盖 | 紧凑单行播放栏，音色面板折叠 |

这些是首轮实现的候选断点，需用 320/360/390/430px 宽与 280–430px 高的横屏组合校准，不能按手机型号硬编码。

### 4.3 竖屏具体布局

- 品牌一行呈现；空间不足时保留方块图标及短名称，不挤成不可读的两行。
- 视角改为一个“视角”入口，展开透视/俯视/正视和“适配舞台”；保持所有功能可发现，不仅依靠快捷键。
- 顶部保留设置与更多；无限模式、分享、清空、玩法收进更多。清空放在操作组末尾，与高频动作拉开间距。
- 播放、撤销、重做始终可达；撤销/重做可放播放区上方独立工具行，不要求全部塞进一行。
- BPM 作为可点击数值；点击在原位置或紧邻区域出现数字输入，提交后恢复数值显示，避免跳转整个设置抽屉。
- 材料列表可折叠为“音色 · N/8 开启”；展开为单独区域，名称包含中文音色说明和静音状态。
- 音符编辑条只在选中时出现，占据布局空间；不能浮在播放键上。出现后重新测量舞台可用区域。
- 触屏主要点击目标至少 44×44 CSS px，目标之间建议留 8px；命中区不得互相重叠。

### 4.4 横屏具体布局

- 使用紧凑播放行：播放/暂停、撤销/重做、BPM、时间位置。进度条可独立占一条较薄但可触控的行。
- 默认折叠材料列表，不让八个材料标签横跨舞台。展开时使用受控侧栏或抽屉，并重新分配舞台空间。
- 工具栏与播放栏高度按实际测量扣除，舞台使用中间剩余矩形，禁止靠固定 bottom 值相互堆叠。
- 当有效高度极低，次要信息折叠到设置；版权说明保留可访问入口，可放入“关于”，不遮挡播放和系统手势区域。
- 舞台应尽可能占满有效空间，但完整适配不等于让格子无限缩小。提供清晰“适配舞台”和放大能力；若操作空间仍不足，允许用户选择减少可见列数，不能静默改曲长或删除内容。

### 4.5 地址栏、安全区与横竖屏切换

- 根布局使用动态视口高度能力并提供回退；四边考虑 safe-area，尤其是横屏左右缺口与底部手势区。
- 布局容器变化通过 ResizeObserver 测量；浏览器 visual viewport 的 resize/scroll 作为补充，统一合并到下一帧处理，避免多条路径重复适配。
- 页面缩放保留浏览器可访问性能力，不用禁止用户缩放掩盖溢出。舞台区域继续管理自己的 touch-action，面板保持正常滚动。
- 预设相机：尺寸变化后按有效矩形重新适配当前窗口的完整包围盒，包括音符高度、舞台边缘和手柄。
- 自由相机：地址栏微小变化不抢用户视角；真正横竖屏切换保留角度和相对缩放，按新 fit distance 重新约束距离和平移。
- 切换方向时取消当前指针事务，避免旧坐标继续驱动新画布。
- 增加始终能找到的“适配舞台”，为极端平移/缩放提供恢复路径；不会修改作品、播放位置或历史。
- 键盘弹出时优先保证输入框和提交入口可见；关闭键盘后恢复布局，避免每个 visual viewport 变化都重置相机。

### 4.6 验收

- 320、360、390、430px 竖屏与 667×375、844×390、915×412、800×280 横屏，没有页面级横向溢出或关键按钮裁切。
- 默认/适配构图中，舞台包围盒落在有效矩形内；主动放大后允许裁切，但“适配舞台”可恢复。
- 顶栏、材料区、音符编辑条与播放栏的命中区域不与可编辑网格重叠。
- 首次打开、转视角后旋屏、缩放后旋屏、地址栏展开/收起、软键盘开合均测试。
- 实机复测用户提供的横竖屏场景，保留包含浏览器 UI 的截图和页面 viewport 数值；与原图并排确认问题消失。

## 5. UX-03：撤销、恢复与破坏性操作

### 5.1 常驻历史入口

复用 `History.canUndo/canRedo`，在 HUD 增加撤销与重做按钮；无历史时真实 disabled，并给出可访问名称。不要再建立第二套历史栈。

统一在 record/push/undo/redo/clear 和手势提交后同步按钮状态，避免只更新某一种输入路径。连续绘制仍是一笔一次撤销；选择、相机移动、打开面板不入历史。新编辑清空 redo，达到历史预算后按钮仍正确。

### 5.2 抽屉中的反馈

推荐在抽屉容器内增加固定的操作反馈区域，位于滚动内容之外、但属于该 dialog 的焦点范围；主页面继续使用 toast。

- 清空或载入示例从抽屉触发时，反馈显示在该抽屉内，包含明确的结果和撤销按钮。
- 面板关闭后，未过期反馈转交主页面；不能同时留下两个可执行的旧回调。
- toast 可自动消失，但撤销能力通过常驻按钮保留；hover、键盘焦点停留时暂停带操作提示的计时。
- 如清空后原按钮禁用导致焦点失效，将焦点移动到反馈中的撤销按钮；普通保存状态更新不抢焦点。
- 反馈引用当前历史操作标识。发生新的编辑后，旧“撤销清空”提示失效，不能在点击时误撤销另一次操作。
- 全局 z-index 只用于视觉分层；可点击反馈必须处于当前模态焦点范围中，不能仅靠调高层级解决。

### 5.3 清空动画与数据一致性

当前 `clearAnimated` 通过 dieQueue 逐步移除方块，`capture()` 又从场景读取音符。首轮实测没有覆盖全部竞争时序，以下作为实现前必须验证的风险。

推荐将清空的逻辑提交与视觉销毁分离：提交时曲谱立即为空；动画使用独立的临时视觉对象，随后释放。所有保存、调度和历史读逻辑状态，不能读半清空的动画状态。

若选择较小改动，至少提供统一的“完成/取消清空队列”入口，并在保存、撤销、重做、载入前调用；该退路也必须保证最终状态原子化。

- 清空只记录一次前态；重复点击不重复压历史。
- 动画中立即撤销恢复完整前态，并取消旧队列，旧动画不能继续删掉恢复后的同坐标音符。
- 清空后重做得到完全空曲，不是动画中间状态。
- 减少动态效果时使用同一数据提交路径，只省略视觉效果。
- 清空与载入前备份行为统一；当前 clearAll 未调用 saveBackup，不能把文档中的“可恢复清空前作品”当成已有实现。

### 5.4 验收

桌面和手机分别测试：清空后立即撤销、动画中重做、提示超时后撤销、面板内撤销、连续载入两首示例、新编辑使旧提示失效、刷新后恢复备份。当前会话的撤销栈不承诺跨刷新保存；跨刷新恢复明确走备份槽。

## 6. UX-04：可信的保存状态与作品保全

### 6.1 状态模型

建议新增小型保存协调模块 `src/persistence.ts`；底层存取仍在 song.ts，main 只提交变更，HUD/config 展示状态。

| 状态 | 文案 | 触发 |
| --- | --- | --- |
| local | 保存在此浏览器 | 启动、无待保存改动 |
| dirty | 有修改，等待保存 | 曲谱改变，防抖计时中 |
| saving | 正在保存… | 实际写入期间，可很短 |
| saved | 已保存到此浏览器 · 刚刚 | 写入成功 |
| failed | 未保存到本机 | 配额、访问限制或其他写入失败 |

沿用约 500ms 防抖；同一会话使用递增 revision 标识改动，保存结果只能确认它对应的版本。未来若写入改成异步，不允许旧结果覆盖更新的 dirty/failed 状态。

### 6.2 底层结果与失败交互

`saveLocal` 和 `saveBackup` 返回可判别结果，例如 `{ok:true}` 或 `{ok:false, reason:'unavailable'|'quota'|'unknown'}`；不把异常对象直接展示给用户。`getStorage` 失败也必须返回失败，而不是当成没有需要保存的内容。

- 只有成功才更新 lastSavedAt。失败不覆盖最后成功时间，也不显示“刚刚保存”。
- 设置内提供“重试保存”“复制分享链接”，主界面以低干扰状态显示未保存；同类失败不反复弹 toast。
- 复制分享链接失败时继续使用可手动选择复制的链接区域；不能把“链接已生成”当成“已复制”。
- 长链接提示潜在截断，后续可加本地作品文件导出；文件格式及导入校验属于单独后续任务，不作为本轮唯一保全方案。
- 备份失败时明确告知不能保证刷新后恢复。对于会替换整首作品的操作，提供“继续替换 / 取消”选择，先保留当前内存状态。
- 在 visibilitychange 到 hidden/pagehide 时尝试提交最新已完成的编辑；不能只依赖 beforeunload。多事件到达时保持幂等，后台不得弹交互提示。
- 未完成的手势按统一规则取消或提交后保存，不能保存半拖动或半清空状态。
- 存档、偏好、备份分别标识：主音量偏好失败不等同于曲谱丢失；不要用一个含糊的“保存失败”覆盖所有状态。

### 6.3 兼容与验收

继续使用现有曲谱 key 和 v1/v2/v3 解码兼容。新增 UI 状态不进入分享码或曲谱历史，不借此重命名旧 `midi` 字段。

验收覆盖：正常修改后刷新、配额异常、Storage 访问异常、失败后恢复存储并重试、连续修改合并、刚修改就切后台、备份失败再载入示例、分享链接成功/拒绝权限。明确断言磁盘中的作品和 UI 状态，而不只检查 toast 文案。

## 7. UX-05 / UX-08：音符选中与触屏编辑条

### 7.1 选中状态

用 `selectedNote = {step,row} | null` 表示 UI 选择，不持久化、不进入分享和历史。用坐标重新查找当前音符，避免保存已被撤销/替换销毁的 mesh 引用。

- 点击音符选中；再次点击同一音符保留选择，不重复开关面板。
- 点击背景清除选择，同时允许超过阈值后开始旋转；点击空格保持原有绘制行为。
- 拖动成功后选择跟随新位置；交换落点时选择跟随被拖动的音符。
- 删除、清空、载入、撤销/重做后重新校验选择；无法确认同一音符时清除选择，不错误指向另一个占据原格子的音符。
- 打开模态抽屉时收起编辑条；关闭抽屉可恢复仍然有效的选择。

### 7.2 编辑条内容

顺序建议：“音色与位置” → “降低半音 / 音高值 / 升高半音” → “试听 / 删除 / 关闭”。窄屏可分成信息行和操作行。

- 初版单次点击 ± 改一个半音；不加长按连发，减少指针取消和历史合并复杂度。
- 对同一音符连续调音可复用现有约 900ms 合并规则；切换音符、删除或其他编辑必须结束合并。
- 修改先判断是否真正变化，再记录历史；到达上下限时禁用对应按钮，不制造空撤销条目。
- 每次改音可短试听，尊重主音量和静音状态；“试听”不改变曲谱或播放位置。
- 删除进入现有统一删除路径，更新曲长、选择、历史与保存状态。

### 7.3 音高的正确表达

当前 `rows.ts` 定义 BASE_MIDI=12、MIN_MIDI=0、MAX_MIDI=24；audio 使用 `2^((midi-12)/12)`。它是以采样为基准的偏移索引，不是标准 MIDI note number。

- 首轮稳妥显示“音高 12/24 · 基准音”及相对半音数，避免直接把 12 显示为 C0。
- `rows.ts` 注释给出 F#4=12，可作为旋律音色的预期映射；要显示音名/八度，必须先确认各采样的基准与实际播放一致。
- Bass、打击乐等不保证共享同一绝对基音；未经核验的音色显示相对半音，不能统一贴上 F#4。
- 提取纯格式化函数到 `src/note-label.ts`，把音高索引、绝对音名和节拍位置区分清楚，添加边界测试。
- 保留现有存档字段和分享编码，仅补展示层与必要的音色元数据。

### 7.4 位置读数

用户显示以 1 为起点：`小节=floor(step/16)+1`、`步号=step%16+1`；进一步显示拍号时每 4 步为一拍。

例如 `step=19` 显示“第 2 小节 · 第 4 步”，不能混用绝对步号。长曲窗口滑动时仍读绝对位置，不能随 viewStart 重置为第 1 小节。

桌面悬停显示只读信息，不抢焦点；触屏以选中编辑条显示。俯视图增加稀疏小节/节拍标尺，密度由投影间距决定，空间不足时隐藏次要刻度。纯信息图层不拦截网格指针。

## 8. UX-06：键盘、焦点和可访问性

按“当前控件 → 当前模态区域 → 页面快捷键”的顺序处理键盘。

- button、switch、checkbox 等保留 Space/Enter 原生行为；文本、数字输入与 contenteditable 保留编辑语义。
- Space 只在舞台或页面背景焦点时播放/暂停。点击舞台后将焦点置于合适的舞台容器，确保鼠标点击播放后不会永远让按钮吞掉页面快捷键。
- Ctrl/Cmd+Z 在输入框内先用于文本撤销，在舞台用于曲谱撤销；无效历史不执行。
- 模态抽屉打开时，快捷键不得修改背后的舞台；如要保留播放操作，应在抽屉内提供明确的播放按钮。
- Escape 按优先级取消活动手势、关闭最上层弹层、关闭编辑条；一次按键不连锁关闭多个层级。
- 抽屉切换需取消旧的延迟归还焦点，避免前一个抽屉关闭定时器把焦点抢回页面。
- 播放位置每帧更新不通过 live region 连续播报；保存成功、失败与操作结果只播报必要变化。
- 数字输入名称具体化为“曲长小节数”“可见列数”“主音量百分比”“混响百分比”，避免多个控件都叫“数值”。
- 本轮可保证 UI 控件键盘可达；canvas 网格完整键盘作曲是后续独立任务，不把按钮可达等同于全功能无障碍完成。

## 9. 可重开的玩法与反馈文案

新增“玩法”入口，桌面可直接显示，手机在更多中；复用抽屉容器，不新增强制全屏欢迎流程。

首次轻提示只讲三件事：播放示例、画出音符、选中后编辑。完成动作或主动关闭后收起，仍能从玩法重开。引导版本记录在独立偏好字段，存储失败时也不反复打断当前会话。

| 场景 | 建议文案 |
| --- | --- |
| 触屏舞台 | 点按或拖动画音符；点音符可调音 |
| 触屏视角 | 单指拖背景旋转，双指移动或缩放 |
| 桌面舞台 | 拖动画音符，滚轮调音，右键删除 |
| 音色列表 | 点击切换该音色静音 |
| 保存成功 | 已保存到此浏览器 |
| 保存失败 | 未保存到本机，你仍可继续编辑 |
| 清空后 | 已清空 N 个音符 · 撤销 |
| 空舞台 | 画下第一个音符，或载入示例 |

不单纯依赖屏幕宽度判断输入方式：结合 pointer/hover 能力和最近使用的 pointerType，兼容触屏电脑与外接鼠标手机。静音状态除颜色外增加图形或文字标记；避免材料按钮看起来像乐器选择器，实际却在静音。

| T14 | 滚动抽屉、关闭或打开另一个抽屉 | 焦点不逃逸、不被旧关闭定时器抢走 |
| T15 | 编辑后立即切后台再回来 | 最新已完成编辑仍在，保存状态准确 |
| T16 | 地址栏、软键盘开合 | 无关键控件裁切，无不必要相机重置 |
| T17 | 旧分享码与已有本地存档恢复 | 内容兼容，新增 UI 状态不污染数据 |
| T18 | reduced-motion 下清空与恢复 | 与常规模式同样的数据结果 |

测试产物建议放 `docs/ux-audit/after/`，包含场景、viewport、浏览器、构建版本、是否真机和结果；失败项保留复现步骤，不用“看起来正常”替代断言。

## 13. 风险与发布检查

| 风险 | 处理 |
| --- | --- |
| 双指接管撤销误伤之前的笔触 | 只回滚本次活动事务；测试完成笔触再双指的路径 |
| 新 viewport 与拾取坐标不一致 | canvas 尺寸、投影、raycast 使用共同矩形；测试四角格子 |
| 框选式 UI 让原本拖动变迟钝 | 只增加空间阈值，不等待长按计时；保留实时预览 |
| 旋屏适配抢用户视角 | 区分轻微尺寸变化与方向变化，保留角度及相对缩放 |
| 层级修复造成键盘访问不到撤销 | 把反馈放入当前 dialog 内，实测 Tab 与返回焦点 |
| 清空动画残留删除恢复后的音符 | 事务取消时清理队列和视觉对象，按操作代次隔离 |
| 状态文本声称保存成功但写入失败 | 以持久化结果确认状态，测试真实 localStorage 内容 |
| 相对音高被错误标为标准 MIDI | 保留偏移展示，逐音色验证绝对音高 |

发布前必须：构建通过、P1 验收通过、真机手势与横竖屏验证完成、旧存档兼容通过、没有新增未处理异常。未验证的环境明确保留为限制，不以桌面模拟替代。
