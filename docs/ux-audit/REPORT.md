# 用户体验实测 · 2026-10-18

## 结论

保留体素舞台、暖色背景和轻量控制栏。优先改善操作可发现性、触屏编辑和误操作恢复，不需要先做视觉重设计。本次仅审查、实测并记录，未修改产品源码。

## 环境与范围

- 当前工作区版本；结束时 HEAD 为 `a7aadc4`。
- Chromium，1440×900、1280×720、390×844。手机为窄屏模拟，未做真机触摸、Safari 或实际听音验证。
- 首先复用 5191 开发服务；该服务中途停止，引发音频资源连接失败，不计为稳定服务下的产品加载故障。后续使用本地 preview（5192、以及本次启动的 5193）检查交互。
- 软件 WebGL 出现 ReadPixels 性能警告。桌面首屏截图使用默认分辨率；后续交互将测试浏览器渲染像素比临时降为 0.5，未修改代码，不能据此给出真实设备帧率结论。
- `npm run build` 通过；有 JS 分包体积警告。

## 已复现问题

### P1：设置内清空后，手机用户点不到撤销

390×844 打开设置 → 清空舞台。页面创建“已清空 33 个方块 / 撤销”，但撤销按钮中心命中的是 `#settings-body`，提示被整个抽屉盖住。设置抽屉 z-index 为 9，toast 为 8，且提示只有约 5 秒。示例载入也共用这套反馈机制。

建议：将操作反馈放入当前抽屉可见区域，或清空后关闭抽屉并把焦点移到恢复入口；另提供常驻撤销/重做入口。仅提高 toast 层级还需处理抽屉焦点约束。

位置：`src/style.css` 的 `.toast` / `.drawer`，`src/main.ts` 的 `clearAll` / `loadExample`，`src/drawer.ts`。

证据：[手机清空后的设置页](mobile-clear.png)。

### P1：自动保存失败仍显示“自动存档 · 刚刚”

在隔离测试浏览器内让 `Storage.prototype.setItem` 抛出 QuotaExceededError，再把 BPM 改成 123。界面显示“自动存档 · 刚刚”，当前 BPM=123，本地已存 BPM 仍为 108。测试后恢复原生方法。

根因：`saveLocal` 静默吞掉异常且不返回结果；`markDirty` 无条件更新保存时间。

建议：保存函数返回成功/失败，仅成功时更新已保存状态；失败保留演奏能力，同时提示“未保存到本机”并提供复制分享链接等保全入口。

位置：`src/song.ts:366`、`src/main.ts:77`。

### P2：空格劫持控件的键盘操作

打开设置，焦点放在“循环”开关，按 Space。实测 loop 保持 true，playing 从 false 变成 true。全局监听先 preventDefault，阻止按钮的原生空格激活。

建议：按钮、开关等交互控件保留原生键盘语义；舞台/页面背景焦点才使用空格播放。若产品坚持全局空格播放，需要明确提示并为开关提供一致的替代操作。

位置：`src/main.ts:1139`。

### P2：移动布局的常用按钮过小

390px 宽度测得：BPM +/- 为 20×15 CSS px，视角按钮为 29×26，顶部工具为 33×33；品牌文字被压成两行。控件基本可达，但密集排列增加误触成本。

建议：触屏命中区向 44×44 靠拢；BPM 点击数值进入编辑；将不常用工具收进“更多”，保留播放、撤销、编辑等高频入口。

位置：`src/style.css:665`、`src/style.css:1584`。

## 代码与界面确认的体验缺口

### P1：触屏缺少音高编辑，撤销依赖键盘或短暂提示

音高修改仅绑定 canvas wheel；触屏没有对应按钮或音符编辑面板。撤销/重做已有完整逻辑，但没有常驻按钮。触屏删除可通过拖出舞台完成，不能说完全无法删除，但精确删除与调音的路径仍不完整。

建议：点击音符后显示轻量编辑条，包含音名、半音 +/-、删除；工具栏增加撤销/重做。保留现有拖动手感，避免点击选择与拖动竞争。

位置：`src/main.ts:1076`、`src/main.ts:935`、`index.html`。

### P2：首次上手缺少可重新打开的说明

桌面操作提示在首次舞台操作后消失，窄屏 `.hint` 直接 display:none。手机材料按钮还隐藏英文音色名，新用户不容易知道材质行是静音控制，也不知道怎样改变音高或恢复误操作。

建议：提供可随时打开的“玩法”入口；首次引导只讲三个动作：播放示例、画音符、编辑/删除音符。触屏与鼠标用不同文案，并在材质行给出明确的静音状态。

位置：`src/hud.ts:332`、`src/style.css:1584`、`index.html`。

### P2：精确作曲缺少读数

滚轮调音只有顶面颜色变化和声音反馈，没有可见音名/八度；没有当前悬停格子的明确小节、步号和音色读数。透视舞台适合探索，但重复编排时只能凭位置与耳朵确认。

建议：悬停或选中音符显示“音色 · 音名 · 小节/步号”；俯视编辑时显示节拍标尺。此项是体验建议，尚未做用户可用性测试。

位置：`src/scene.ts` 的 `setPitch`、`src/hud.ts`。

## 已通过的基本流程

- 俯视网格点击新增：33 → 34 个音符；Ctrl+Z 后回到 33。
- 从示例面板载入第一首：56 个音符，载入前备份存在。
- 设置能打开，Esc 能关闭；数值框可提交 BPM。
- 循环播放状态可以启动；未据此声称音频主观听感通过。

## 建议实施顺序

1. 修复撤销被挡、保存误报与空格冲突。
2. 补常驻撤销/重做、触屏音符编辑与足够的触控命中区。
3. 补可重开的玩法说明、音高和节拍读数。
